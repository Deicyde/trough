# Physlib: The Lean Physics Library

[Physlib](https://github.com/leanprover-community/physlib) is, in its README's words, “An open-source, community, project to digitalize results from physics into Lean 4”. The README adds: “Physlib was formed by merging the general physics Lean library PhysLean (formerly called HepLean) with the quantum-information library Lean-QuantumInfo.” The repository holds three libraries, as the README presents them: Physlib, the core library; PhyslibAlpha, downstream of it under a lighter review; and QuantumInfo, quantum information theory in a codebase of its own. The README names the project's maintainers: Léo Lessa, Alex Meiburg, Daniel Morrison, Zhi-Kai Pong, Rodolfo Soldati, Joseph Tooby-Smith and Winston Yin.

- Repository: [leanprover-community/physlib](https://github.com/leanprover-community/physlib), read at commit [2a1dfe43](https://github.com/leanprover-community/physlib/tree/2a1dfe43134b49b643642f13d33031754021bb5d) (2026-11-12), the newest commit of its `master` branch whose build passed.
- Lean toolchain v4.35.0, Mathlib v4.35.0, [56a00585](https://github.com/leanprover-community/mathlib4/tree/56a005855ea17e0b0958f73ec801ae140b0a1679).
- License: Apache-2.0.

The repository's handbook asks that a file be organized around a single definition and named after it, so the map has an article per module with a declaration: 1,549 articles, 645 in [Physlib](physlib/README.md), 827 in [PhyslibAlpha](physlibalpha/README.md) and 77 in [QuantumInfo](quantuminfo/README.md). A part per library has a page per area, per folder below it and per deeper folder with an API map, 216 folder pages in all; a module in another deeper folder is on the page of the nearest folder above, under a line naming its folder.

An article quotes the module's docstring and its section docstrings, their headings shown as the article's and a table of contents left out, and shows each declaration in file order: its name, kind and line, its docstring and its Lean statement (the text up to the `:=` or `where` that starts its value, or the whole text of a structure, class or inductive type). The articles hold 28,307 declarations, 865 of them instances with no name, and 17,007 have a docstring; 677 private declarations are counted on the articles, not shown. The repository keeps the keyword `theorem` for the significant results its [scripts/lint/exemptions/Theorems.txt](https://github.com/leanprover-community/physlib/blob/2a1dfe43134b49b643642f13d33031754021bb5d/scripts/lint/exemptions/Theorems.txt) lists, “usually one known by name”: 476 of the declarations here are among them, and their blocks say so and lead their cards' Lean rows. No declaration's value read here contains `sorry`.

The API maps, the repository's own accounts of an area with citations of the declarations that formalize it, are quoted on the pages of their folders, without the sentences they mark as not yet formalized. Informal results (`informal_lemma`, `informal_definition`, `semiformal_result`) and TODO items are not mapped, and the parts of a docstring that mention a TODO item are left out, each cut marked with …: the map records what the library has, not what it plans. 35 modules hold nothing else, only such text or private declarations, and have no article.

The text is read from the source without Lean, by the reading trough uses for other libraries: a declaration's name is read under the namespaces it sits in, and its line is the line its keyword is on. The dependencies come from Lean. The data workflow fetches the repository's build cache with Mathlib's, imports every module of the three libraries, and reads which other modules' declarations each module's declarations use: in a statement, which here takes in a definition's value and a structure's fields, or in a proof. An article depends on the modules whose declarations its statements use (“Statement uses” on the site), and its proof depends on those that only its proofs use; a dependency already reached through another is left out. That gives 2,134 statement edges and 452 proof edges. An edge says that some declaration of one module uses some declaration of the other, not which one. The same reading checks the names read from the source: a declaration whose name Lean does not have, such as one private to its module, is left out, 24 declarations at this commit.

The docstrings, Lean statements and API maps are quoted from [leanprover-community/physlib](https://github.com/leanprover-community/physlib) at commit [2a1dfe43](https://github.com/leanprover-community/physlib/tree/2a1dfe43134b49b643642f13d33031754021bb5d), under its Apache-2.0 license.
