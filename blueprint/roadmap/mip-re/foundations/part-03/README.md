# Sampler to The class is contained in the…

## Normal form verifiers

Games produced in the proof are presented by pairs of Turing machines: a *sampler*, generating questions by a rigid linear-algebraic procedure that introspection can certify, and a *decider*, checking answers.

- [Sampler](def-sampler.md)

Comments. This follows the query interface of the paper's `def:sampler` (`linear.tex`) (AuditSync26) at field size $2$, the only size the normal form verifiers of this blueprint use; the paper's samplers over $\mathbb{F}_{2^t}$ reach this form by downsizing (Section [Conditionally linear functions and samplers](../../structure-of-the-proof/README.md)). Two interface details matter here. The correctness clauses for $\mathtt{linear}$ and $\mathtt{factor}$ are imposed only for prefixes in the range of $L^w_{\lt j}$, as the paper's amended definition states, and are well defined there by Lemma [Structure of a CL function](../../structure-of-the-proof/part-01/lem-cl-structure.md). The paper additionally requires bounded-prefix format and length checks: after computing $s(n)$, a sampler inspects only the prescribed prefix of each auxiliary input, rejecting with a fixed default when the format fails. Together with totality, this bounds the paper's absolute $\mathsf{TIME}_\mathcal{S}(n)$ uniformly over even malformed or overlong inputs. A total program that scans an ignored, arbitrarily long suffix would not satisfy that source contract.

In Lean the machine is a program of the ambient cost model (Section Computability conventions), its well-formed input is the pair of $n$ and a query (`Sampler.Query`), and `Sampler.TimeBoundAt n T k` is a *relative cost bound*: it requires halting within $T\cdot(\left\vert {d} \right\vert+1)^k$ on every input $(n,d)$, well formed or not. It is a separate predicate, not a bound $\mathsf{TIME}_\mathcal{S}(n)\leq T$ on the absolute supremum. In particular, neither this predicate nor the totality field supplies the paper's bounded-prefix contract.

Two departures from the paper are forced here, and both were found by trying to prove the bound for a concrete machine rather than by inspection. First, the paper's bound is *uniform* over all inputs, and that reading is not available in the ambient model: a value is inspected in place one node at a time, but a loop carries the rest of a list to its next iteration only by copying it, so no program walks an unbounded list within a cost independent of its length, and a uniform bound is met by no sampler or decider that checks the length of a string against an unbounded $s(n)$. The running time is therefore bounded by a polynomial in the size of the input. Second, the *degree* $k$ of that polynomial has to be carried alongside the coefficient $T$, because every decider of the pipeline runs another program through the universal machine, whose overhead is a polynomial $Q$ of degree above one (`Cost.Universal.univPoly`): a simulated run costing $T (\left\vert {d} \right\vert+1)^k$ becomes one costing about $Q(T (\left\vert {d} \right\vert+1)^k)$, of degree $k \cdot \deg Q$. No fixed degree is closed under the composition the deciders perform; a bounded degree is. Collapsing the two into one parameter — reading the bound as $T (\left\vert {d} \right\vert+1)^T$ — would also be closed, but then $\lambda$-boundedness would allow degree $n^\lambda$ in the input size, which is not a polynomial-time condition at all and would make Theorem [Gap-preserving compression from ambient stage contracts](../../structure-of-the-proof/part-09/thm-compression.md) assume compression of verifiers its proof cannot compress.

**Remark (Comparison with the source normal-verifier contract).** The paper's `def:normal-ver` requires an operational first step: compute $s(n)$ and check both question lengths before continuing. Its `def:normal-game` uses answer strings of length at most the finite absolute time $\mathsf{TIME}_\mathcal{D}(n)$ (`games.tex` (AuditSync26)). The dimension check yields $s(n)\leq\mathsf{TIME}_\mathcal{D}(n)$ in that machine model. These source requirements are not the checked ambient definition above.

Relating executions in the two models and identifying the source answer cut are part of the pending normalization in Remark The runtime-contract bridge remains an obligation. An ambient relative-cost coefficient need not be the source absolute time, and increasing an answer cut may change the value. In the ambient model acceptance is halting with output $1$; the relative time bound ensures totality with input-dependent budgets. The dimension bound needed by the pipeline is required independently in Definition [$\lambda$-bounded verifier in the ambient model](def-lambda-bounded.md).

**Remark (The synchronization invariant).** An earlier arrangement of the pipeline of Section [Structure of the proof](../../structure-of-the-proof/README.md) asked two properties of the games it produces, neither of which follows from symmetrizing the players' roles. The pipeline no longer needs either, its soundness being carried in $\mathrm{val}^*$ throughout (Remark [Why the pipeline is bipartite throughout](../../structure-of-the-proof/README.md)); the two are recorded here because they are what a synchronous route would have to establish, and because the second is the reason there is no synchronous route:

1. *Synchronicity*: equal questions reject unequal answers, so that ${\mathrm{val}^{s}}$ is defined at all. For a game given by a game description this holds by fiat (Definition [Game description](../part-02/def-game-description.md)); for a game given by a normal form verifier it is a condition on the decider. It would be needed wherever ${\mathrm{val}^{s}}$ occurs; direct repetition preserves it, since two unequal answer tuples to equal question tuples differ in some coordinate, where the repeated game rejects.
2. *Common marginals and diagonal weight*: the game's two marginals agree, with common marginal $\nu$, and the almost-synchronous transport requires $\mu(x,x)\geq\kappa\nu(x)$ for every $x$, with the same $\kappa > 0$ along the whole recursion. This is the hypothesis of Theorem [Almost-synchronous strategies are near synchronous strategies](https://github.com/vidick/MIPRE-formalization/blob/5926bdff5db621f44682a101007ef2fe3ae8d970/blueprint/src/content/03_background_results.tex#L137), without which the two values of a game are unrelated (Remark [The diagonal-weight hypothesis cannot be dropped](https://github.com/vidick/MIPRE-formalization/blob/5926bdff5db621f44682a101007ef2fe3ae8d970/blueprint/src/content/03_background_results.tex#L180)).

The second property is emphatically not one of repeated games: the $k$-fold repetition of a game with diagonal weight $\kappa$ has diagonal weight $\kappa^k$. A synchronous route would therefore have to establish it for the constructions of introspection, oracularization and answer reduction — never inheriting it from the game being compressed, and never applying the transport to a repeated game — and in (JNVWY20) both properties come from the typed structure of the samplers, which this blueprint does not carry (Section [Departures from the paper](../../introduction/README.md)). Neither is established here, and neither needs to be.

- [$\lambda$-bounded verifier in the ambient model](def-lambda-bounded.md)

**Remark (Comparison with source boundedness).** The paper's `def:lambda` instead requires $\mathsf{TIME}_\mathcal{S}(n),\mathsf{TIME}_\mathcal{D}(n)\leq n^\lambda$ in the absolute-time model, for $n\geq2$, and $\left\vert {\mathsf{V}} \right\vert\leq\lambda$ (AuditSync26). The source dimension bound follows from writing the sampler's output and from the decider's initial checks. This condition and the marked ambient definition above are different contracts; their comparison requires the normalization obligation below.

**Remark (The runtime-contract bridge remains an obligation).** The paper's transformation contracts use absolute simulation budgets and, where stated, standard timeout form. They cannot be applied to `Verifier.IsBounded` solely by reinterpreting $\mathsf{TIME}$: even on inputs of size $O(N^\lambda)$ the relative budget $N^\lambda(\left\vert {d} \right\vert+1)^\lambda$ can be much larger than $N^\lambda$. A normalization bridge must supply bounded-prefix behavior and the required timeout form, preserve the sampler distribution and the chosen finite game, and transfer the relevant completeness witnesses. It must keep the original answer cut by rejecting longer answers rather than silently enlarging the alphabet when it increases the simulation budget. Any new absolute bound, for example $N^{p(\lambda)}$, must then be propagated through the transformation parameters. This is a pending bridge between the source and ambient interfaces; the existing conditional Lean results do not construct it.

- [The class $\mathrm{MIP}^*_{1,1/2}(2,1)$](def-mipstar.md)

The paper's definition (`games.tex` (AuditSync26)) has the decider run in time $\mathrm{poly}(\left\vert {z} \right\vert)$ “even for long inputs $a,b$”, which its footnote makes precise by having the decider return $0$ whenever the four strings are too long. In the ambient model a program reads a list only by walking it (the discussion under Definition [Decider](def-decider.md)), so the time bound is stated in the total input length and the footnote's clause is a separate requirement; the game on the strings of length at most $B$ is then the paper's finite game, and the two readings define the same class. A randomized machine is a deterministic program with an explicit uniform seed of the length $B$ of its time bound, and for the same reason the sampler's time is bounded by $P$ in its total input length $\left\vert {z} \right\vert + \left\vert {r} \right\vert = \left\vert {z} \right\vert + B$: a program cannot read a seed of length $B$ within time $B$, and with $B$ polynomial in $\left\vert {z} \right\vert$ the bound is still $\mathrm{poly}(\left\vert {z} \right\vert)$. In Lean the verifier is a `PolyVerifier`, the clause is `PolyVerifier.Efficient`, the game is `PolyVerifier.game` and the class is `MIPRE.MIPStar`.

**Remark (Comparison with the source complexity class).** Definition [The class $\mathrm{MIP}^*_{1,1/2}(2,1)$](def-mipstar.md) is the paper's $\mathrm{MIP}^*_{1,1/2}(2,1)$ up to the readings of the time bounds recorded after it. The checked halting reduction (Theorem [Halting reduction](../../structure-of-the-proof/part-09/thm-halting.md)) has two forms. Along the criterion route it supplies its game as an explicit description computed with no time bound — the tabulation of a verifier at a level exponential in the machine's size, whose questions no polynomial-time sampler can write down — which is what the computable class of Definition [The computable class](def-mipstar-computable.md) asks for. Along the paper's route it supplies the verifier $\mathsf{V}^{\mathsf{halt}}$ at the fixed level $C$ with $\lambda = \mathrm{poly}(\left\vert {\mathcal{M}} \right\vert)$ (Lemma [The parameter of the halting verifier](../../structure-of-the-proof/part-09/lem-lambda.md)), played on input $z$ by a polynomial-time sampler and decider, which is what Definition [The class $\mathrm{MIP}^*_{1,1/2}(2,1)$](def-mipstar.md) asks for; so Theorem [$\mathrm{MIP}^* = \mathrm{RE}$](../../the-main-theorem/thm-mipstar-eq-re.md) holds for both classes (`MIPRE.Halting.mipstar_eq_re`, `MIPRE.Halting.mipstarComputable_eq_re`), and Lemma [The class is contained in the computable one](lem-mipstar-poly-sub.md) is the inclusion of the first in the second. General bipartite games must be represented in `GameData` with value-preserving transport; merely forcing unequal answers to equal questions to lose can destroy a perfect strategy, which is why both tabulations tag the two players' questions apart.
